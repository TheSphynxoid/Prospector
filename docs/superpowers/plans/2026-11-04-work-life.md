# Work-life Area and Currency Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Track applications (with follow-up reminders), won work, payments, accounts and transfers in a new Work area, on top of daily automatic exchange rates.

**Architecture:** A `prospector.fx` module owns rates (fetched daily, stored per day). Three new repos (`ApplicationRepo`, `WorkRepo`, `AccountRepo`) hold the data; `prospector.worklife` holds the flows (lead applied → application, follow-ups, won → work). A new `make_work_router` serves `/work/*` pages built from Jinja templates under `templates/work/`, using the existing HTMX/toast patterns.

**Tech Stack:** FastAPI, Jinja2, HTMX 2.0.4, SQLite (schema.sql, `CREATE TABLE IF NOT EXISTS`), APScheduler 3, httpx, pytest + respx.

**Spec:** `docs/superpowers/specs/2026-11-04-work-life-design.md`

## Global Constraints

- English UI copy, sentence case. Amounts: USD first, TND equivalent under it (`≈ 2,460 TND`).
- Amounts stored as integer thousandths (`*_milli`). Never floats in tables except rates.
- Supported currencies: `("USD", "EUR", "TND", "GBP")` — one constant, `prospector.fx.CURRENCIES`.
- "Today" is the Africa/Tunis date (`prospector.store.stats.TZ`), never UTC.
- Rate sources, in order: `https://open.er-api.com/v6/latest/USD`, then `https://cdn.jsdelivr.net/npm/@fawazahmed0/currency-api@latest/v1/currencies/usd.json`.
- Rate sanity: positive, finite, within ±20% of the last stored value for that code.
- Built-in fallback rates: TND 3.0, EUR 0.92, GBP 0.79.
- `followup_days` setting: default 7, 1–60.
- Every page works at phone width; HTMX in-place actions with the existing `toast` HX-Trigger (with undo where an undo exists).
- Tests: `.venv/Scripts/python -m pytest -m "not slow" -q` (uv is not on PATH).
- Work on a branch `work-life`; `git push` needs `env -u GITHUB_TOKEN`.

## Review Focus

1. Amount typed as `1 200,50`, `1,200.50`, `0`, `-5`, `abc`, or empty → the first two parse to 1200.5; the rest are rejected with a field error, nothing saved. (Task 1: `test_parse_amount_*`.)
2. A rate source answering 200 with TND missing, a string, or a 10× jump → that value is ignored, the next source or the last known rate is used, nothing raises. (Task 1: `test_fetch_rejects_*`.)
3. Pressing *Applied* twice, or applying from two tabs → exactly one application per lead. (Task 4: `test_applied_twice_one_application`.)
4. A follow-up due "today" at 00:30 Tunis time (23:30 UTC the day before) → shows as due. (Task 3: `test_due_uses_tunis_date`.)
5. Archiving an account that received payments → payments and their history stay, the account disappears from pickers only. (Task 5: `test_archived_account_keeps_payments`.)
